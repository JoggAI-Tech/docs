title: "MCP Troubleshooting"
description: "Resolve JoggAI MCP availability, OAuth, scope, upload, and asynchronous task issues."
---

## The MCP endpoint returns 404

JoggAI MCP is controlled by a deployment feature flag. A `404` from `https://api.jogg.ai/mcp` means the hosted endpoint is not enabled in that environment yet; it is not fixed by installing an npm package or cloning a GitHub repository.

Contact [support@jogg.ai](mailto:support@jogg.ai) to confirm beta availability.

## npm cannot find `@joggai/mcp-client`

An npm registry `E404` is different from an MCP endpoint `404`. It means the
installer package is not available from the registry configured on that
computer, or the current account cannot access it.

Check:

```bash
npm config get registry
npm view @joggai/mcp-client version
```

Do not install an unverified similarly named package. Use the manual client
instructions while the official package or registry access is being resolved.

## Installation reports a conflicting entry

The installer does not overwrite a same-named MCP server that points elsewhere.
Inspect the existing configuration and only replace it when you intend to:

```bash
npx -y @joggai/mcp-client status <client>
npx -y @joggai/mcp-client install <client> --replace
```

Replacement logs out and removes only that named entry before rebuilding it.

## Codex reports that OAuth is unavailable

Confirm the server was added with both the registered client ID and MCP resource:

```bash
codex mcp get JoggAI --json
```

The configuration must contain:

```text
url: https://api.jogg.ai/mcp
oauth_client_id: codex
oauth_resource: https://api.jogg.ai/mcp
```

Remove and add the entry again if those values are wrong. Then run:

```bash
codex mcp login JoggAI
```

## The OAuth callback is rejected

For Codex, let the CLI create its own loopback callback. A custom callback domain, fixed path, `localhost` hostname, or manually overridden HTTPS callback will not match JoggAI's restricted `codex` registration.

For ChatGPT, Claude, Cursor, or a custom agent, the redirect URI must exactly match the URI registered with JoggAI. Contact support when the client changes its callback URI.

## Login succeeds, but tools are missing

MCP tool discovery is scope-aware. A tool is omitted from `tools/list` when the token does not include its required scope.

Reauthorize the connection and approve the needed permissions. If a Space administrator restricts a permission, use a permitted workflow or ask the administrator to grant access. Starting a new agent conversation may be required to refresh the discovered tool list.

Review the complete [scope table](/mcp/authentication#tool-scopes).

## Cursor says installed, but JoggAI is not connected

For Cursor, installation means the MCP JSON configuration was written. OAuth is
still a Cursor UI action. Restart Cursor, open **Customize > MCP**, select JoggAI,
and complete sign-in before expecting tools to load.

## ChatGPT installation returns `manual_action_required`

This is expected. ChatGPT does not expose a local configuration API. Follow the
returned action in **Settings > Connectors** using the JoggAI MCP URL and public
client ID instead of retrying the npm command.

## A tool returns an audience or resource error

The access token must be issued specifically for `https://api.jogg.ai/mcp`. A token for the REST API or an existing JoggAI plugin has a different audience and cannot be reused.

Log out and run the MCP OAuth flow again. Do not manually paste a token from another integration.

## A generation call times out

Submission tools return a task ID for long-running operations. A client-side timeout does not prove that the remote job failed.

Ask the agent to query the existing task ID before submitting again:

```text
Check the current JoggAI task and resume polling it. Do not submit a duplicate
generation request unless the existing task is confirmed failed or missing.
```

## An upload tool did not upload the file

The MCP tool creates a signed upload URL; it does not transfer the file bytes. The client must send the file directly to that URL using the returned method and headers before using the uploaded asset in another tool.

Signed URLs expire. Request a new upload URL rather than editing or reusing an expired signature.

## Authentication keeps failing

Check that:

- The MCP beta is enabled for the target environment.
- The client ID and exact redirect URI are registered.
- The OAuth resource is exactly `https://api.jogg.ai/mcp`.
- Browser login completes in the intended JoggAI account and Space.
- The local Codex callback listener is still running when the browser redirects.
- A corporate proxy or firewall is not blocking the MCP endpoint or local loopback callback.

Never send OAuth tokens, authorization codes, API keys, signed media URLs, or private source files to support. Include the client name, timestamp, selected Space ID, and sanitized error message instead.
