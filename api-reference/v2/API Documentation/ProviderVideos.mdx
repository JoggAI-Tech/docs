---
title: "Provider Video Generation"
description: "Use supported official video-provider fields with one JoggAI asynchronous task and billing model."
---

Provider video endpoints are thin OpenAPI adapters over JoggAI's existing video
generation pipeline. They reuse the current provider integration, model availability,
queue, status, refund, and pricing behavior.

<Warning>
Every create request is billable. Cost depends on the active model configuration
and may vary by duration, resolution, audio, reference mode, or multi-clip options.
The request is rejected when the model is unavailable or the combination has no price.
</Warning>

## Workflow

<Steps>
  <Step title="Upload media">
    Upload every reference image, video, or audio asset through JoggAI first.
    Provider endpoints accept Jogg OSS asset URLs, not file bytes or arbitrary URLs.
  </Step>
  <Step title="Submit once">
    Call the explicit provider endpoint and retain the returned `task_id`.
  </Step>
  <Step title="Poll one status endpoint">
    Call `GET /open/v2/videos/tasks/{task_id}` until the task succeeds or fails.
    Do not replay a billable create request because polling timed out.
  </Step>
</Steps>

```bash
curl --request POST \
  --url 'https://api.jogg.ai/open/v2/runway/videos/generations' \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "gen4_turbo",
    "promptText": "A slow camera move through a bright modern kitchen",
    "promptImage": "https://res.jogg.ai/provider-assets/kitchen.jpg",
    "ratio": "16:9",
    "duration": 5
  }'
```

Requests use strict JSON decoding. Official fields that are not supported by the
current JoggAI pipeline or price configuration return `400` rather than being ignored.
